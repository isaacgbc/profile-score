<objective>
Build the JSON-to-text converter that bridges Apify's structured output and the audit orchestrator's expectations. Two exports:
1. `profileToSectionRecord(p: HarvestProfile): Record<string, string>` — produces exactly the shape `linkedinSections` uses in Stage 2 of the orchestrator, with keys matching `LINKEDIN_SECTION_IDS` from `linkedin-parser.ts`. ## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Apify response -> formatter | Untrusted external data; formatter must never crash on unexpected shapes |
| Formatter -> orchestrator | Trusted structured output; orchestrator consumes as plain strings |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 (T-07: log injection / markdown injection into Claude prompts) | Tampering | `profileToMarkdown` | accept | The markdown is fed to Claude, not rendered as HTML. React JSX escaping protects downstream UI. Markdown syntax characters in profile text (e.g., `#`, `*`) may confuse Claude's parsing but cannot execute anything. Per 01-RESEARCH.md §Don't Hand-Roll row 7: "conservative whitelist" is unnecessary here. |
| T-05-02 (Malformed actor output causes TypeError) | DoS | Formatter helpers | mitigate | Every field access is optional-chain guarded; every array check uses `.length` guard; every helper returns `""` on empty input. Tests 12-13 enforce no-throw on empty profile. |
| T-05-03 (T-10: cache poisoning via special characters in normalized output) | Tampering | `profileToSectionRecord` keys | mitigate | Output keys are hardcoded string constants (`headline`, `summary`, etc.) — never derived from user input. Values are trimmed strings from the HarvestProfile. No dynamic key construction. |
| T-05-04 (Recommendation PII leakage via >3 recommendations) | Information Disclosure | `formatRecs` | mitigate | `MAX_RECOMMENDATIONS = 3` constant + `.slice(0, MAX_RECOMMENDATIONS)` per D-18. Test 7 enforces. Limits PII exposure to what the brief explicitly permits. |
| T-05-05 (T-02: scraped PII flows through multiple layers) | Information Disclosure | All output | accept | Scraped data IS PII. Downstream layers (cache, orchestrator, LLM prompts) are the storage and transmission gates. This plan transforms shape, not exposure. Cache TTL + 24h retention (Plan 01-03) is the compensating control. |
</threat_model>
